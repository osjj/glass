# Glarivo 产品页文案复用流程

首批示例：[2026-09-23 三款商品文案](./product-page-optimization-pilot-20260923.md)。这份流程供后续逐批处理商品页；每款必须有自己的产品事实和采购理由，不能把同一组卖点复制到几十个页面。

## 每次怎么启动

给出 3–5 个 SKU 或商品网址即可。若希望我代选，给出优先类目或客户类型；其余可由我根据现有商品页、可核实的资料和内容缺口筛选。优先处理有询盘价值、规格较完整、能体现不同容量/杯型/工艺/用途的代表款。若有 Search Console 查询或已有询盘，可用它们调整顺序。

可直接复制下面这段发给我：

> 按 Glarivo 首批三款商品页的流程，优化下一批产品页面。商品 SKU/链接：[填入；或写“请从某类目代选 3–5 款”]。目标客户/市场：[可选]。已确认的定制、包装、MOQ、交期或检测资料：[可选]。请先核对线上商品和图片，写出每款独有的英文文案，再更新后台并验证公开页面。保留 SKU、事实参数、图片和网址；无法证实的卖点先标记，不要编造。

## 逐款制作

1. **核对事实。**记录 SKU、名称、容量及单位、口径/高度/底径及单位、材质、装箱、用途、工艺和现有图片。对照商品资料或样品解决标题与参数矛盾。把“已证实”“页面已有但待确认”“未知”分开。
2. **确定购买理由。**选一个主要客户和采购场景，回答这款与同类款有何不同、适合怎样的使用或陈列、客户下单前还要确认什么。型号级事实放产品页；普遍选购问题放分类页或 Blog 指南。
3. **写后台字段。**商品名称写产品类型和真实差异点；型号已有 Item No. 行，不必再塞进主标题。`summary` 用于目录和搜索描述的备用来源；真正显示在商品详情的重点是 `features` 和 `contentSections`。每款建议写 3–5 条独有卖点、1–2 段围绕选型/定制/包装的正文，并单独写 `seoTitle`、`seoDescription`。站点会自动在 SEO 标题后追加 Glarivo Glassware。
4. **检查图片。**确认主图、详情图、尺寸图和包装图属于同一型号；图片说明描述实际可见内容。发现其他型号的图片或说明时，先核实实物，再替换或修改。
5. **发布与验收。**保存原文案修订记录，保持商品网址及已核实的规格/图片记录。公开页面逐页检查 HTTP 200、H1、SEO 标题和描述、卖点、正文、规格表、canonical、手机排版及询盘按钮。数据库已更新不等于网页已更新，必须打开线上网址确认。
6. **观察结果。**记录发布前后 Search Console 的商品页查询、展示、点击，以及询盘中出现的 SKU 和问题。以客户是否更容易选型和询价作为内容质量依据，不以字数作为目标。

## 必须先确认的商品资料

| 项目 | 供应商/产品负责人需确认的内容 |
| --- | --- |
| 型号与容量 | SKU、各变体、容量数值和单位、满口容量与建议使用量的区别 |
| 尺寸与材质 | 口径、高度、底径、重量、材料及测试报告适用型号 |
| 供货 | 装箱、内盒、MOQ、现货、样品、价格及交期 |
| 定制 | 可用工艺、颜色、Logo 位置、打样与验收标准 |
| 性能 | 耐热、洗碗机、食品接触和认证等说法的具体证据 |
| 图片 | 每张图是否属于对应 SKU，是否展示实际提供的工艺/包装 |

没有证据的供货或性能承诺不要写成事实；可以改成客户询价时应提供的信息，或留待资料补齐后再发布。

## 自己在后台操作时

进入 `/admin/products`，打开对应商品，按已核实资料修改名称、摘要、SEO 标题与描述、Details 卖点、规格和 Ordered content sections。详情页有卖点时，备用 `description` 不会替代可见卖点；把主要文案写入 `features` 和文字区块。后台 AI 改写可用于形成候选句，但最终仍需逐项核实数字、单位、工艺及商业承诺。保存后打开公开商品网址检查实际渲染。
